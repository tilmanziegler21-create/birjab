# Telegram UX: простой режим по умолчанию

Дата: 2026-10-11. Paper runtime и 24-часовой watch не останавливались. Стратегия, БД и LiveAdapter не менялись.

## Зачем

Бот уже считает состояние верно, но экраны были написаны для разработчика. Снаружи нужны четыре ответа: работает ли бот, во что вошёл, чего ждёт, сколько заработал.

## Два режима

- **Обычный** — по умолчанию. Главная, позиции, сделки, почему нет сделок, AI / новости, статус.
- **Экспертный** — кнопка внизу меню. Добавляет A/B, живую техническую панель, raw-причины риска, тики, reject counters.

Автопанель каждые 10 с теперь обновляет **простую главную**, не технический дамп. В экспертном режиме автопанель снова показывает прежний live-экран.

## Главная

На живом снимке (тик ~960):

- статус: бот работает, PAPER, live отключён, рынок Binance Public;
- баланс 1000 / в заявках 150 / свободно 850 USDT;
- активные сделки 0, ждут входа 3, закрытых 0;
- прибыль за 24 ч и зафиксированная прибыль — по факту из API;
- «Ждёт отката для входа по BTC, ETH, SOL»;
- ближайшие входы по трём монетам;
- XRP отдельно: лимит активных монет 3 из 3.

С главной убраны A/B, слово equity, режим UNKNOWN, `max_active_pairs ×N`, дельты 5м/1ч/24ч, длинные MOCK-пояснения.

## Остальные экраны

- **Позиции** — карточка на монету: куплено / ждёт входа / неактивно, уровень, текущая цена, до входа, сумма.
- **Сделки** — только закрытые циклы + сводка (всего, сумма, средняя, доля прибыльных). Времени входа в `/api/state` нет, поэтому оно не выдумывается.
- **Почему нет сделок** — человеческий текст по каждой монете. Raw `max_active_pairs ×N` только в эксперте.
- **AI / Новости** — кратко: MOCK, нет LLM, режим, блокировки, 3 события.
- **Статус** — работает / лента / последний тик. Эксперт добавляет A/B и служебные счётчики.

Подписи: общий капитал, в заявках, зафиксированная прибыль, текущий результат, закрытые сделки, позиции.
