# Telegram dashboard verification

Дата: 2026-10-11. Живой PaperRuntime и 24-часовой монитор не останавливались.

## Что сделано

- Живая панель `/live` (кнопка «Живая панель»). Обновление через `editMessageText` каждые 10 с, новое сообщение не плодится.
- «Обновить сейчас» редактирует то же сообщение (`Reply.edit`).
- «Почему нет сделок?» — фактические причины Strategy / RiskManager и дистанция до BUY.
- Время везде в **Europe/Berlin** (`дд.мм.гггг чч:мм:сс CEST/CET`).
- Цены только из `/api/state` (Binance Public). Δ5м / Δ1ч / Δ24ч — из публичных klines, если запрос удался; иначе «—».
- Режим рынка показывается только если есть свечи; иначе «нет истории». Иллюстративные 84 250 / DEMO на панель не попадают.
- Отдельные уведомления BUY/SELL как раньше (не правка панели).
- RetryAfter обрабатывается паузой и повтором. «message is not modified» игнорируется.

## Mini App

Существующий React dashboard на `http://127.0.0.1:8000` уже опрашивает `/api/state`. Telegram Mini App потребует:

1. Публичный HTTPS (не localhost).
2. Проверку `initData` (HMAC) на backend.
3. Отдельный read-only маршрут, не торчащий в интернет вместе с SQLite.

Сейчас Mini App **не внедрялся**: это выставило бы API наружу. Живая панель в чате закрывает наблюдение без публикации порта.

## Как смотреть

1. Написать боту `/live` или нажать «Живая панель».
2. Не открывать старое сообщение `/start` — оно статичное. Живёт то, которое бот правит.
3. `/why` — полный список причин простоя.
